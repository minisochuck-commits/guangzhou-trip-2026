# 演示版内容与交付约定

## 数据边界

公开版本必须使用虚构访客、日期与活动，不存票面全名、个人电话、订位编码、票号、护照、内部通知或讨论记录。示例日期为2026年，不代表真实预订。酒店、公共地点与公开前台电话可以作为公开示例保留。

## 页面结构

每行是一位访客某天的安排；四种内容合成活动与交通、餐饮与住宿两列，加日期/人员首列。人员选择只筛行；日期按钮跳转；相同完整内容可合并。默认第五位示例访客。链接使用 guest1–guest5 与 all，语言为 zh、en、ar。三语必须内容一致，阿语RTL。表格不横向滚动。

指南依次为欢迎、出发前准备、酒店、琶洲、城市故事、城市概况、品牌公开介绍、科技、礼拜与清真餐、饮食、生活习惯、商圈、半日路线、中文短句、资料来源。既有布局保持；演示活动弹窗只放合成资料。

## 验证

运行 `npm run check` 和正式构建。随后在390px真实浏览器核中文、英文、阿语、选人、日期跳转、指南展开、演示资料、关闭弹窗、图片和页面宽度；静态包也要检查个人信息。离线更新应清除本应用旧缓存。自动检查不代表所有者已经认可页面。

## 发布

从源码构建静态包，不手改生成物。只发布经核查的静态目录与干净源码快照。发布文件不包含工作目录、构建缓存、旧业务文档或原始活动图片。修改最新版本不等于清除了历史副本；需要单独核旧分支、历史文件URL、原托管及缓存。用户选择沿用原仓；2026-10-21 又明确要求一并清理旧提交与旧 Sites。日常发布不重写历史；这次个人信息清理是单独授权的一次历史迁移，完成后需要重新克隆。不得从旧克隆恢复原始个人资料。
