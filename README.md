# 广州行程 Guangzhou Visit · 2026-09-20 – 2026-10-07

MINISO Egypt 一行 5 人赴广州的行程分享页。手机优先，三语（中文 / English / العربية），
公开访问，无登录无密码。

- 站点原始 starter 文档（vinext / Sites 生命周期、D1、Wrangler 等）保留在
  [`docs/VINEXT_STARTER.md`](docs/VINEXT_STARTER.md)。
- 设计与取舍记录在 [`DESIGN_NOTES.md`](DESIGN_NOTES.md)。

## 页面结构

**用户明确否定了分开的「吃住行」tab。** 要求是：选好人和日期之后，同一屏里就能知道
当天的活动、交通、餐饮和住宿，不用来回切 tab。所以吃住行已经并入当天行程，
只剩两个 tab。

手机首屏（顶部，sticky）：

1. 一行标题 + 紧凑语言切换（中文 / English / العربية）
2. 次要行：日期区间 `20 SEP – 07 OCT 2026`
3. 查看对象横滑（全部 / 5 个单人），点击高度 ≥ 44px，英文简称按票面拼法原样显示

再往下是一条**折叠**的红色短提示（展开才显示完整说明），然后是两个 tab：

| Tab | 内容（自上而下） |
| --- | --- |
| 当天行程 | 日期导航 → 当天事件（有时刻的按真实时间轴排序）→「时间待定的安排」→**当天吃住行**（餐饮 → 用车 → 住宿，每张卡默认露第一条摘要，其余收进「详情」折叠）→ 9/26 城市体验建议 → 人员名单（折叠） |
| 来华指南 | 网络、支付、地址（可复制中文地址）、证件、餐饮、落地、时间；底部官方来源链接 |

页尾（两个 tab 都能看到）：折叠的**待确认清单**、折叠的**参考：总部通知**、一行页脚。

**查看对象切换是阅读筛选，不是权限隔离。** 页面本身是公开的，所有语言、所有人的行程
在同一份公开数据里；切换只决定当前显示哪些条目。

- 「全部」视图把同一场安排合并成一张卡，并在卡片底部列出参与者。
- 单人视图只保留该人参与的事件，以及按他所在分组筛出来的当天吃住行。
- 同组同行的吃住行合并成一张卡（例如学习组一张、接待组一张），个人视图里仍显示整组名字。

## 状态口径（不要改写）

| 标记 | 含义 |
| --- | --- |
| 已确定 Confirmed | 已经定下来的事实（航班、已确认的参会日） |
| 建议安排 Suggested | 只是建议，**没有预订、没有安排** |
| 待确认 To confirm | 还没定，需要有人去定 |

页面任何地方都不得把「建议安排」写成已预订 / 已安排。

### 加 / 改当天的吃住行

`LOGISTICS` 是吃住行事实的**唯一正本**，`lib/day-plan.ts` 用
`logisticsLines("<block-id>")` 逐条引用它的原句，不另抄一份 —— 改事实只改
`LOGISTICS`，两边不会漂。`InfoBlock.id` 是联合类型 `LogisticsBlockId`，写错 id 编译期就报。

`daySupplements(date)` 里按日期分支产出卡片，规则（都是当前已核定的口径，改之前先确认）：

- **出行日 9/20、9/28、10/6、10/7**：只给一句「机场及机上餐食供应与饮食需求，
  请出发前确认」。不出酒店卡、不出用车卡 —— 当天已经有真实的接送 / 到场事件，
  再加一张会重复。当天算谁在路上，是从 `EVENTS` 里当天的 `flight` / `ground` 事件反推的，
  跨日的阶段性提示不算。
- **9/21 抵达日**：一张抵达用餐卡（写明两批到达时间不同）+ 三张住宿卡；
  不出用车卡，因为两次接机已经是当天的事件。
- **9/22–23**：学习组=会议供餐待确认 + 往返会场用车；QIUTING=订货会供餐 + 往返用车；
  接待组=商务活动餐饮 / 用车待定。三组各自一张住宿卡。
- **9/24**：学习组=学习日三餐建议（未预订）+ 往返门店用车；
  QIUTING=**是否参加上午场未定**，餐饮与用车随之未定；接待组同上。
- **9/25**：学习组 + 接待组同上；**QIUTING 起进入返乡阶段，不再出现广州酒店 / 会务餐 / 广州用车**。
- **9/26**：学习组=自由活动餐饮与路线待定；接待组=商务活动待定；两组住宿卡标明这是最后一晚。
- **9/27**：只出一张「退房后用餐」（待接待人协调确认），参与者是当天 17:25 那一批
  （HASSAN / AHMED / RAHMA）。**不出住宿卡** —— 当天是退房 + 夜班机，不能显示又住一晚。
  REHAM 的延迟退房 / 日间房、晚间陪同接待交接，已经在当天的事件卡里，这里不重复。
- **9/29–10/5**：没有任何吃住行卡，只有 QIUTING 的返乡阶段事件卡。

`showsCityIdeas()` 控制 9/26 的城市体验建议：只给**学习组和全员**看 ——
返乡的 QIUTING 不该看到广州游玩建议。

### 加 / 改一条行程

在 `lib/trip-data.ts` 的 `EVENTS` 里增删对象。要点：

- 三语 `title` 必填；`summary` / `details` / `pending` 按需要给。
- `people` 决定这条在谁的视图里出现；写全所有参与者，全员视图靠它合并显示。
- `status` 只能是 `confirmed` / `suggested` / `pending`，对应上表三种标记。
- `date` 用 `YYYY-MM-DD`；跨日阶段用 `endDate`，**区间里的每一天都会出现在日期导航上**，
  并在这些天里重复显示同一张卡（接待组 9/22–26、QIUTING 9/25–10/5 都要能逐日点开）。
- `time` + `tz` 一起给才算「有确切时刻」。有时刻的事件按**真实时间轴**排序
  （北京 UTC+8、开罗 UTC+3），所以 9/21 的开罗 00:20 会排在成都 08:00 前面，
  跨时区和午夜不会颠倒。
- **没有时刻的事件不要编时间**，它们会自动归到当天的「时间待定的安排」一段里。
- 航班用 `flight` 字段；出发地是 `CAI` 时自动标开罗时间，否则标北京时间。
